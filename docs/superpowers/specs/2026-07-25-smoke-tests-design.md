# Deployment Smoke Tests — Design

**Date:** 2026-07-25
**Status:** Approved
**Roadmap line:** Tier 4 "scripted smoke tests", promoted from polish to the
top of the backlog by the outage in PR #12.

## Problem

Live log streaming was broken in every real deployment for 11 days
(2026-07-14 → 2026-07-25, fixed in PR #12) while **every check was green**:
server 204/204, web 62/62, and all six CI jobs passing on every PR in that
window.

Nothing tested the assembled product. `server` and `web` are each tested in
isolation, `contract` compares two type files, and `images` proves the
Dockerfiles build — but no job has ever *run* what it built. The specific
defect lived in `web/nginx.conf`: nginx's `$host` dropped the port, so the
server compared `Origin: http://localhost:8080` against `Host: localhost`
and rejected every WebSocket upgrade. That file is not reachable by any
unit test in either package.

This is a whole class, not one bug. The proxy layer also owns SPA fallback
routing, `/api` forwarding, session-cookie passthrough, and the WS upgrade
headers. All of it currently ships unverified.

## The critical insight

**Asserting HTTP 101 would not have caught the outage.**

`@fastify/websocket` completes the WebSocket handshake *before* the route
handler runs. During the outage the upgrade therefore succeeded — a real
`101 Switching Protocols` — and only then did the handler emit a `1008`
close frame. (That is why `LogPanel` could render the reason text
"Origin not allowed" at all: receiving a close *reason* requires a
completed handshake.)

A smoke test that stops at "did the upgrade succeed" would have passed
throughout the outage. The test must inspect the **first frame's opcode**:

```
opcode = firstByte & 0x0f
  0x1 → text frame  → log data flowed   → PASS
  0x8 → close frame → rejected upstream → FAIL
```

That single nibble is the load-bearing assertion of this entire feature.

## Constraints

- **No root `package.json`.** The repo is two independent packages plus a
  bare `scripts/` directory. `scripts/sync-types.mjs` establishes the
  precedent: a dependency-free `.mjs` run as `node scripts/<name>.mjs`.
- **Node's global `WebSocket` cannot send custom headers.** It follows the
  browser API, which forbids setting `Cookie` and `Origin` — the two
  headers this test exists to exercise. A browser-shaped client is
  therefore unusable here.
- **The demo fleet is part of `docker-compose.yml`** (`demo-nginx`,
  `demo-redis`), so the stack has containers to list and stream without
  extra fixtures. `demo-redis` emits ~5 KB of startup output immediately,
  making it the reliable stream target; `demo-nginx` can sit silent until
  it receives a request.
- **GHCR packages are private** and `docker compose pull` returns 403, so
  the smoke stack must build locally rather than pull.
- CI runs npm 10; every added `package.json` is another lockfile exposed to
  the npm 11 rewrite trap. Adding zero is preferable.

## Design

Three new files and one CI job. No changes to `server/` or `web/` source.

### `scripts/smoke.mjs`

Dependency-free, Node 22, exits 0 on success and 1 on the first failure,
printing one line per step so a CI failure names the step that broke.

Four assertions, chosen because each one can *only* break at the
deployment seam:

1. **`GET /`** → 200 and the body contains `<div id="root">`. Proves nginx
   serves the built SPA and the `try_files` fallback is intact.
2. **`POST /api/login`** with `Origin: <base>` → 200 and a `session` cookie
   in `set-cookie`. Proves the cookie survives the proxy.
3. **`GET /api/containers`** with that cookie → 200, a JSON array, and at
   least one entry whose name contains `demo-redis`. Proves the authed API
   path and that the Docker socket mount works.
4. **`GET /api/logs/:id`** upgraded, sending `Cookie`, `Origin`, and the
   WS handshake headers → `101`, then **the first frame's opcode is `0x1`,
   not `0x8`**, with a non-empty payload.

Step 4 is written against `node:http`'s `upgrade` event, reading the raw
socket. Only the opcode nibble and the payload length are parsed — server
frames are unmasked, and the test never needs the decoded text, only proof
that a text frame with content arrived.

Configuration via environment, defaulting to the fixture so the script runs
against any stack:

| Var | Default |
|---|---|
| `SMOKE_BASE_URL` | `http://localhost:8080` |
| `SMOKE_USER` | `smoke` |
| `SMOKE_PASSWORD` | the `.env.smoke` password |

A 30-second overall timeout, and a 10-second wait for the first WS frame,
so a hung stack fails with a clear message rather than the job's 10-minute
ceiling.

### `.env.smoke`

A committed fixture holding a `smoke` user (admin role), its scrypt hash
generated by `server`'s existing `npm run hash-password`, and a throwaway
`FLEET_SESSION_SECRET`. Header comment states plainly that it is a CI
fixture for an ephemeral stack and must never be copied to `.env`.

This is a real committed credential. It is acceptable because the stack it
guards exists for roughly 90 seconds inside a disposable runner and is
never network-reachable — but the file is named and commented so nobody
mistakes it for a template.

### `smoke` job in `.github/workflows/ci.yml`

```
cp .env.smoke .env
docker compose up -d --build
poll http://localhost:8080/api/health until ok, 60s cap
node scripts/smoke.mjs
on failure: docker compose logs   (so a remote failure is diagnosable)
always:     docker compose down -v
```

The health poll targets `/api/health`, the one unauthenticated route, and
checks the `ok` field rather than merely a 200 — `ok` is false when the
Docker socket is unreachable, which would make step 3 fail confusingly
later.

`images` gains `smoke` in its `needs`, so a stack that fails smoke never
publishes to GHCR.

**Accepted cost:** compose rebuilds both images, duplicating the `images`
job's build (~1–2 min). Sharing built layers between jobs needs artifact
plumbing or a registry hop, which is more machinery than the minutes are
worth at this scale.

## Alternatives rejected

- **Use `ws` from `server/node_modules`.** More readable than hand-rolled
  frame reading, but the smoke job would need `npm ci` in `server` to reach
  one transitive dependency, and the script would silently depend on
  another package's tree. Rejected for a 3-line opcode check.
- **A third `smoke/` package with vitest.** Best test ergonomics, but a
  third `package.json` and third lockfile — more surface for the npm 10/11
  trap that already cost time today — to run four assertions that need no
  test framework.
- **Non-blocking (`continue-on-error`) job.** A red check nobody must act
  on becomes decoration. The gap this closes went unnoticed for 11 days
  precisely because nothing forced attention.
- **Covering mutating actions or deploy/rollback.** Real coverage, but
  those paths have server-side tests, they mutate the demo fleet mid-run,
  and deploy needs a pullable image that currently 403s. The untested seam
  is the proxy.
- **Playwright or a real browser.** Would exercise the actual client, but
  it is a heavyweight dependency and a new flake surface for assertions
  that are fundamentally about HTTP and WS headers, not rendering.

## Testing

The smoke script *is* the test; it has no unit tests of its own. Its
correctness is established by construction:

- Run it against the current stack → passes.
- Revert `web/nginx.conf` to `proxy_set_header Host $host`, rebuild, run →
  **step 4 must fail on opcode `0x8`**. This is the mandatory verification:
  a smoke test that cannot detect the outage it was built for is worthless.
  Restore afterwards.

Both runs are performed and their output recorded before this ships.

## Docs

A README line under the existing testing notes describing
`node scripts/smoke.mjs` and its env vars, plus a CLAUDE.md gotcha noting
that the proxy layer is covered *only* by this script and that the opcode
check is deliberate rather than incidental.

## Out of scope

- Mutating actions, deploys, rollbacks, rate limiting, and the audit viewer.
- The stream cap and heartbeat behavior from PRs #11/#12 — concurrency and
  half-open sockets are not smoke-test material.
- Any change to `server/` or `web/` source.
- Making GHCR packages public, though it would let the job pull instead of
  build.
